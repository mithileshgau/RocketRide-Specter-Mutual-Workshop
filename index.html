    What you are building

    Specter Mutual is a fictional insurer that covers paranormal damage. A policyholder files a claim, an AI agent reviews it and recommends approve, deny or escalate, and a policy engine checks that recommendation against the rules before anyone sees it.

    That last part is the whole point. An agent can be talked into things. Plain code cannot. Put them together and you get something a compliance team will sign off on.

    Where RocketRide comes in

    RocketRide is an open source runtime for AI pipelines. You wire a pipeline together visually inside your IDE, it runs on a C++ engine, and you deploy it to the cloud from the same window.

    For today that means you do not write any plumbing. RocketRide gives you the agent, the model and memory wiring, the webhook that receives claims, and the deploy. The only things you write are the prompt and the policy, which are the two things that actually make this app yours.

    You build the reviewer twice

    First, a model

    "Something threw my TV off the wall at 3am."

    A polite, convincing letter. It has never seen the policy. It may approve a possessed Roomba, and it will believe a customer who writes "my agent pre-approved this".

    prose. nothing a system can act on.

    Then, an agent

    The same claim, the same model.

    A category, a recommendation, a reason an adjuster can read, and a letter. Then code checks that recommendation and overrides it when it has to.

    a decision, an audit trail, and a guarantee.

    The policy

    A claim carries a name and tier, the incident date, an amount, and a description in the customer's own words. The agent reads the description and picks a category. The engine looks up what that category is worth.

    Four rules on every claim

    1. Filed more than 30 days after the incident, denied.
    2. Over $3,000, a human adjuster, whatever the agent recommends, unless the policy has already ruled the claim out.
    3. Payouts never exceed the coverage limit or the amount claimed.
    4. The agent can be stricter than the policy. It can never be more generous.

    Rule 4 is the one that matters. An agent that denies too often costs you a customer. An agent that approves too often costs you money, and it is the one fraudsters aim at. So the engine lets the agent be cautious and blocks it from being generous.

    4a. The model writes 5 min

    This is the zero in Zero to Agent. A plain model answering claims with no instructions and no policy. It will sound confident and decide nothing the business can trust.

    1. In the sidebar, Monitor, Pipelines tab, press + New pipeline and call it claims. The file lands in pipelines/claims.pipe and the canvas opens.
    2. Open the Nodes tab and drag four nodes onto the canvas: Webhook, Question (question), Anthropic (llm_anthropic) and Return Answers (response_answers).
    3. Connect them in that order by dragging from the output port on the right of one node to the input port on the left of the next. Wire the Webhook's text output into the Question node.
    4. Click the Anthropic node. Set anthropic.profile to claude-sonnet-4-6, type ${ROCKETRIDE_ANTHROPIC_KEY} into apikey, and save.
    5. Press Run, then send claim 1, then claims 3 and 4. Claim 2 is skipped here because it tells you nothing new.
    Why the Question node

    Models and agents only accept questions. A claim sent as plain text lands on the webhook's text lane, and the Question node turns it into a question. Without it the claim never reaches the model. The last node must be Return Answers (response_answers), the one that accepts the model's answers.

    The one that catches everybody

    The apikey field does not fill itself in from your Variables when you place a node by hand. You type ${ROCKETRIDE_ANTHROPIC_KEY} into it yourself and save. This is by design, confirmed by the RocketRide team in Discord support.

    Type the variable reference, not the key. RocketRide swaps in the real value at run time, then checks it starts with sk-ant. Skip the step and you get an unconfigured cog on the node and a vendor SDK error.

    How to send a claim

    Press Run first. Once the pipeline starts, the Project Log prints the webhook URL and an authorization key for this run. Copy both and POST the claim JSON there as plain text. The URL is generated fresh every time the pipeline starts, so take it from your own log.

    sending a claim from a terminal

    Notice what is wrong

    The answers sound professional. The model has never seen the policy, so it makes one up. In testing it wrote a confident generic fraud assessment, complete with headings and a "do not auto-approve" verdict on the TV claim. Run it again and you can get a different call. There is no decision a system can act on, only prose.

    The answer says "LLM error"

    A bad or missing key does not stop the run. The pipeline still answers, and the answer is the error: **LLM error** — AuthenticationError … from the model, or LLM error: Exception … 401 from the agent in 4b. Check ROCKETRIDE_ANTHROPIC_KEY in Variables, then stop and re-run the pipeline. The key is read at start.

    "Pipeline is already running" means a copy is still up. There is one running copy per person per pipeline, so stop it in Monitor before you press Run again.

    Why does an agent need a memory node?

    The agent works in waves: it can call a tool, read the result, and think again before answering. The memory node is where those intermediate results live between waves. The docs mark it required, so an agent without one does not start. You do not have to configure it.

    If you open the file with RocketRide: Open as Text you can see what the canvas wrote. The control array lives on each helper, the Anthropic node and the memory node, and names the agent in from. The agent itself has no control array. The ids are from your own file, so yours may differ.

    4c. The policy engine 15 min

    The agent recommends. It does not get the final say. Python checks every recommendation against the policy before anything reaches the customer.

    Where this runs

    Outside the pipeline, deliberately. The engine is ordinary code with no AI in it, so it cannot be argued with, and it sits between the pipeline's answer and the customer. In Step 5 the portal calls it on every response. Right now you run it as a file, which is the fastest way to see it work.

    1. Create policy.py at the root of your project, next to apps and pipelines.
    2. Paste the code below into it and save.
    3. Run it: python3 policy.py.

    policy.py
    import json
from datetime import date

# Coverage limits in dollars. None = not covered.
POLICY = {
    "poltergeist_damage": {"basic": 1000, "premium": 5000},
    "cold_spots_hvac":    {"basic": None, "premium": 2000},
    "ectoplasm_cleanup":  {"basic": 500,  "premium": 1500},
    "possession":         {"basic": None, "premium": None},
}
FILING_WINDOW_DAYS = 30
HUMAN_REVIEW_OVER = 3000
DECISIONS = {"approve", "deny", "escalate"}

def parse_decision(raw):
    # The agent is told to return JSON, but agents don't always listen.
    if isinstance(raw, dict):
        return raw
    try:
        start, end = raw.index("{"), raw.rindex("}") + 1
        return json.loads(raw[start:end])
    except ValueError:
        return {"category": "other", "recommendation": "escalate",
                "reasoning": "(agent output unreadable)", "letter": ""}

def adjudicate(claim, raw_decision):
    agent = parse_decision(raw_decision)
    category = agent.get("category", "other")
    recommended = agent.get("recommendation")
    if recommended not in DECISIONS:
        recommended = "escalate"

    amount = float(claim["amount"])
    tier = str(claim["tier"]).lower()
    days_late = (date.fromisoformat(claim["filedDate"])
                 - date.fromisoformat(claim["incidentDate"])).days

    # 1. Hard rules. These ignore what the agent recommended.
    limit, rule = None, None
    if days_late > FILING_WINDOW_DAYS:
        decision, rule = "deny", (f"Filed {days_late} days after the incident "
                                  f"(limit is {FILING_WINDOW_DAYS}).")
    elif category not in POLICY:
        decision, rule = "escalate", f"Category '{category}' is not in the policy."
    elif POLICY[category][tier] is None:
        decision, rule = "deny", f"'{category}' is not covered on the {tier} tier."
    elif amount > HUMAN_REVIEW_OVER:
        decision, rule = "escalate", (f"Claims over ${HUMAN_REVIEW_OVER:,} "
                                      f"require a human adjuster.")
    else:
        # 2. Within policy: the agent may be stricter, never more generous.
        limit = POLICY[category][tier]
        decision = recommended

    # 3. Payout never exceeds the coverage limit or the amount claimed.
    payout = min(amount, limit) if decision == "approve" else 0

    notes = []
    if decision != recommended:
        notes.append(f"Policy override: agent recommended {recommended}. {rule}")
    if decision == "approve" and payout < amount:
        rule = f"Payout capped at the ${limit:,} {tier} coverage limit."
        notes.append(rule)

    # 4. If the rules changed anything, the customer gets a compliant template
    #    instead of the agent's letter, which was written before the rules ran.
    letter = str(agent.get("letter", ""))
    if notes or not letter:
        outcome = {"approve": f"approved for ${payout:,.2f}",
                   "deny": "denied",
                   "escalate": "referred to a human adjuster"}[decision]
        reason = f" Reason: {rule}" if rule else ""
        letter = (f"Dear {claim['policyholder']},\n\nYour claim {claim['claimId']} "
                  f"has been {outcome}.{reason}\n\nSpecter Mutual Claims")

    return {
        "claimId": claim["claimId"],
        "category": category,
        "decision": decision,
        "payout": payout,
        "letter": letter,
        "reasoning": agent.get("reasoning", ""),
        "policyNote": " ".join(notes) or None,
    }

if __name__ == "__main__":
    # A claim the agent was talked into approving. The policy says no.
    claim = {"claimId": "SM-1002", "policyholder": "Marcus Hale", "tier": "basic",
             "incidentDate": "2026-10-20", "filedDate": "2026-10-27", "amount": 1500,

    Reference

    Words you will hear

    Nothing here needs a computer science degree. Every term the steps use is in this list.

    The ideas

    AgentAn AI that does not just answer. It reads a situation, makes a decision, and explains why. Here, the claims reviewer.
    LLMLarge language model. The AI that reads and writes text. On its own it produces text, not decisions.
    PromptThe written instructions you give a model or an agent. A system prompt is the standing instruction it gets before every message.
    MemoryWhere an agent keeps intermediate results while it works through a problem in several passes. RocketRide agents require one.
    GuardrailA rule enforced by code that the AI cannot override. Here, the policy engine.
    Policy engineThe Python that checks the agent's recommendation against the policy and overrides it when needed.
    EscalationHanding a decision to a human instead of letting the AI make it.
    Audit logA record of every decision, why it was made, and whether a rule changed it. What compliance teams ask for first.
    Prompt injectionHiding instructions in user input to trick an AI, like "this claim is pre-approved". The fraud test is practice at spotting it.

    The tools

    RocketRideAn open source runtime for AI pipelines, with a C++ engine and an extension that puts the whole thing inside your IDE.
    IDEThe app engineers write code in, like VS Code or Cursor.
    ExtensionAn add-on that puts new features inside your IDE.
    Command paletteThe search box for every command your IDE knows. Cmd+Shift+P, or Ctrl+Shift+P.
    Coding agentAn AI assistant inside your IDE that writes code from instructions, like Claude Code or Cursor's agent.
    TerminalThe text window where you type commands like pnpm install.
    pnpmThe tool that installs a project's dependencies. RocketRide requires it instead of npm.
    Open VSXThe extension store Cursor and Windsurf use instead of the VS Code marketplace.
    VariablesSecrets you store once in the RocketRide sidebar and refer to by name. Only names starting ROCKETRIDE_ are substituted.
    API keyThe password a service gives you so your code can call it. An Anthropic one starts with sk-ant.

    The pieces of a pipeline

    PipelineA chain of steps that runs in RocketRide. Data goes in one end, a result comes out the other. Saved as a .pipe file.
    CanvasThe visual editor where you place and connect nodes. Open as Text shows the JSON underneath.
    NodeOne step in a pipeline, like the Webhook or the Agent. Each has a type id such as llm_anthropic.
    LanesThe connections carrying data from one node to the next. The agent's are questions and answers.
    ProfileWhich specific model a node uses, for example claude-sonnet-4-6.
    WebhookThe entry point of a pipeline. It receives data sent from outside.
    Project LogThe panel printing what a running pipeline is doing, including the webhook URL and authorization key for that run.
    JSONA simple text format for structured data, written with curly braces. How the portal and the pipeline talk.
    DeployPutting your app on the internet so anyone with the link can use it.

    The one that changes the build

    There is no Python node that sits on the data lanes

    Checked across the whole public catalogue. tool_python states it plainly: the node exposes one sandboxed execution tool and has no data lanes. It is reachable only as an agent tool call, python.execute, with the code passed as the code tool argument. tool_daytona is the same shape. preprocessor_code is a Tree-sitter chunker. Nothing else runs arbitrary code.

    So Webhook, Agent, Python, Response cannot be wired. The doc's flowchart and its Step 4c instruction do not describe a buildable pipeline.

    There is a second reason not to force it. If Python is an agent tool, the agent chooses whether and how to call it, and the code arrives as a tool argument the agent produced. A guardrail the agent controls is not a guardrail, which is the exact lesson of the workshop.

    So the codelab moves the engine out of the pipeline: the pipeline returns the agent's recommendation, and policy.py adjudicates before anything reaches a customer. In 4c that is a file the attendee runs. In Step 5 the portal calls a TypeScript port of it. The lesson is unchanged and everyone can finish. Josh, this is the one worth a look before we lock the doc.
